## 1. Цели и задачи тестирования

### Цели:
- Обеспечить корректность работы математических функций для вычисления площади и периметра геометрических фигур

- Создать автоматизированный набор тестов для регрессионного тестирования
- Получить практические навыки написания unit-тестов с использованием фреймворка unittest

1. Разработать набор тестовых случаев для функций расчёта площади и периметра прямоугольника

3. Протестировать граничные условия (нулевые значения, отрицательные значения)
4. Проверить работу с различными типами данных (целые и дробные числа)

## 2. Описание тестируемого продукта

### Общее описание:
Программный модуль для выполнения геометрических расчётов, включающий функции для работы с различными геометрическими фигурами.

### Состав продукта:

#### Модуль `rectangle.py`
Функциональность для работы с прямоугольниками:
- `area(length, width)` - вычисление площади прямоугольника
- `perimeter(length, width)` - вычисление периметра прямоугольника

**Требования:**
- Функции должны принимать два числовых параметра (длина и ширина)
- Должны корректно работать с целыми и дробными числами
- Должны возвращать числовое значение результата
- При отрицательных значениях параметров должны генерировать исключение `ValueError`

#### Модуль `circle.py`
Функциональность для работы с кругами:
- `area(radius)` - вычисление площади круга
- `circumference(radius)` - вычисление длины окружности

**Требования:**
- Функции должны принимать один числовой параметр (радиус)
- Должны использовать константу π (math.pi) для расчётов
- Должны корректно работать с целыми и дробными числами
- При отрицательных значениях радиуса должны генерировать исключение `ValueError`

### Технические характеристики:
- **Язык программирования:** Python 3.x
- **Фреймворк тестирования:** unittest
- **Зависимости:** стандартная библиотека Python (unittest, math)

## 4. Стратегия тестирования

### 4.1 Типы тестирования:

#### Unit-тестирование (основной фокус):
- **Цель:** Проверка отдельных функций в изоляции
- **Инструмент:** unittest (стандартная библиотека Python)
- **Метод:** Автоматизированное тестирование
- **Частота:** При каждом изменении кода

#### Функциональное тестирование:
- Проверка соответствия математическим формулам
- Проверка корректности вычислений
- Проверка обработки различных типов входных данных

#### Тестирование граничных значений:
- Нулевые значения параметров
- Минимальные положительные значения
- Максимальные допустимые значения
- Отрицательные значения (недопустимые)

#### Негативное тестирование:
- Передача недопустимых значений
- Проверка корректности генерации исключений
- Проверка сообщений об ошибках

### 4.2 Методология:

**Test-Driven Development (TDD) подход:**
1. Написание теста перед реализацией функциональности
2. Запуск теста (должен провалиться)
3. Написание минимального кода для прохождения теста
4. Рефакторинг кода
5. Повторение цикла

**Техники тестирования:**
- **Equivalence Partitioning (разбиение на классы эквивалентности):**
  - Положительные числа
  - Нулевые значения
  - Отрицательные числа
  - Дробные числа

- **Boundary Value Analysis (анализ граничных значений):**
  - Проверка поведения на границах допустимых значений
  - Тестирование нулевых значений
  - Тестирование минимальных и максимальных значений

### 4.3 Инструменты и окружение:

- **Язык программирования:** Python 3.x
- **Фреймворк тестирования:** unittest
- **Система контроля версий:** Git
- **Хранилище кода:** GitHub
- **Операционная система:** macOS (Darwin 24.5.0)

### 4.4 Запуск тестов:

```bash
# Запуск всех тестов для модуля rectangle
python -m unittest rectangle.py

# Запуск всех тестов для модуля circle
python -m unittest circle.py

# Запуск всех тестов с подробным выводом
python -m unittest -v rectangle.py circle.py

# Запуск конкретного тестового класса
python -m unittest rectangle.RectangleTestCase

# Запуск конкретного теста
python -m unittest rectangle.RectangleTestCase.test_square_area
```

## 5. Критерии приемки

### 5.1 Критерии успешного завершения тестирования:

1. **Покрытие кода тестами:**
   - Минимум 90% покрытие всех функций
   - 100% покрытие критических путей выполнения
   - Все публичные функции должны иметь тесты

2. **Успешность тестов:**
   - Все unit-тесты должны проходить успешно (зелёный статус)
   - Отсутствие критических ошибок
   - Отсутствие неожиданных исключений

3. **Качество тестов:**
   - Каждая функция должна иметь минимум 3-5 тестовых случаев
   - Обязательное тестирование граничных условий
   - Обязательное тестирование негативных сценариев
   - Наличие понятных описаний (docstrings) для каждого теста

4. **Корректность вычислений:**
   - Все математические вычисления соответствуют известным формулам
   - Погрешность вычислений с плавающей точкой не превышает 10^-5
   - Корректная обработка всех типов входных данных

5. **Обработка ошибок:**
   - Корректная генерация исключений для недопустимых входных данных
   - Понятные сообщения об ошибках
   - Отсутствие необработанных исключений

### 5.2 Критерии отклонения:

Тестирование считается неуспешным, если:
- Хотя бы один тест проваливается
- Покрытие кода тестами менее 80%
- Обнаружены критические ошибки в вычислениях
- Отсутствует обработка исключительных ситуаций
- Код не соответствует требованиям PEP 8
